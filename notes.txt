what changed: check_aggregate now checks the call's first positional
argument in addition to the receiver (np.std(x) puts the series in the
argument, not the receiver, since the receiver is just the module
name), and a literal slice (x[-30:]) counts as already-windowed, same
as rolling/expanding/ewm. Also added collect_top_level_assignments,
which scans a file's top-level statements for name = <windowed expr>
and name = <int literal>, so two more cases resolve: window = x.iloc
[-30:] followed by window.std() on a separate line (fixes
fp_aggregate_bounded_by_slicing.py), and shift(lag) where lag = 3 is
assigned once earlier in the file (fixes the case sample.py's comment
calls out as unresolvable - it no longer is, for this narrow shape).
Both trackers refuse to resolve a name that's assigned more than once
anywhere at the top level, to avoid guessing wrong instead of silently
picking one of several possible values.
