2026/09/11 - inverted check_aggregate from a blacklist to an allowlist.
This is the structural change the last four entries kept circling.

the problem being solved: every fix up to now was negative space - flag
everything, then suppress if windowed, if groupby, if plotted, if
returned. Each manual sample turned up a shape the previous suppression
rules didn't cover, so the list grew and the real hit rate never moved.
A blacklist can only ever cover shapes somebody already sampled.

the inversion: flag only when the value can be shown to reach a
time-ordered decision. Two things count as evidence, and they came from
reading what the confirmed true positives actually have in common, not
from theory:
  - a comparison (price > threshold), directly or via a name
  - a write into a frame column (df['z'] = ... / vol), which is what
    applies one number across every row
Traced one hop: the call itself, or a plain name assigned from it and
used later in the same scope (reaches_decision / name_feeds_decision /
is_column_write / references_name in finder.py). Anything that is only
returned, printed, plotted, or parked in a scalar nothing decides on is
no longer evidence of a decision, so it isn't flagged.

2026/09/11 (last) - fixed the recall regression the census exposed,
before moving on to tiering. Restoring documented true positives, not
pushing residue down.

the fix: a whole-series statistic recombined element-wise with the
series it came from - (df - df.min()) / (df.max() - df.min()) - is a
per-row value that depends on every row. That is the leak itself, no
matter where the result goes afterwards, which matters because in
normalize() it goes out through a return into a caller's column write
one scope away. broadcasts_over_series() tests whether the source
series appears as a bare operand in the same expression, outside any
aggregate call. np.mean(r) / np.std(r) never touches r outside the
aggregates, so a scalar summary does not qualify and fp_posthoc_sharpe
stays suppressed. This is an argument from semantics - broadcast
against summary - not from the corpus.

first run, before any fix: 89 findings (11 high, 78 low) against 11 on
the dev corpus. Read the clusters and the rule was plainly too loose. It
was searching for the series appearing ANYWHERE in the statement, so all
of these counted as a broadcast when none of them are:
  {"min": s.min(), "max": s.max(), "p5": s.quantile(0.05)} - s appears
    bare as the receiver of .quantile(), which is not an aggregate, so
    the walk descended into it. A receiver is not an operand. quantstats
    alone had 24 of these.
  len(x) > 0 and x.std() > 0 - x inside len() is a scalar count.
  [constraint, cp.sum(w) == k] + more_constraints - a list concatenation
    is a BinOp, and the bare w was in a different element of the list.

so broadcasts_over_series now requires the statistic and the series to be
combined ARITHMETICALLY: walk up from the aggregate for a BinOp, UnaryOp
or Compare that also holds a bare use of the series. And contains_bare
stops at three boundaries it used to walk straight through - a collection
literal (a container doesn't combine its elements), an aggregate call
(already did), and any other call that isn't element-wise. That last one
needs a list, ELEMENTWISE_FUNCS (abs, log, sqrt, where, ...), which is
the one place in this file where I'm naming names instead of using a
structural rule. The justification is semantic rather than corpus-fitted:
a series through abs() is still a series and can still be broadcast, a
series through len() or ulcer_index() is a scalar and cannot.
